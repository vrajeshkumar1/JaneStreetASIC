# Host software

MicroPython code for the host: the RP2350 on the Tiny Tapeout demo board, or
any MicroPython board wired to the FPGA build in `fpga/`. It also runs under
CPython, which is how `test/test.py` checks it.

| File | Contents |
|---|---|
| `pe_host.py` | The driver: links to the chip's SPI host interface, a `Chip` class with the operations of `docs/spec.md`, part 2, and host-side helpers for the USB and Ethernet programs |
| `make_programs.py` | Run on a PC: assembles every program in `programs/` (and the self-test program) into `programs.py` |
| `programs.py` | Generated by `make_programs.py`: each program's words and label addresses as plain lists and dictionaries |
| `demo.py` | First check on hardware: the chip's ID, the size registers of all four engines, a program on each engine, and the shared flags |
| `ad3_host.py` | Run on a PC: the Analog Discovery 3 as the host, through the WaveForms SDK, with the same driver and self-test (`fpga/README.md`) |

## Links

`Chip` moves bytes through a link object. Three are provided:

| Link | For | Notes |
|---|---|---|
| `TTBoardLink()` | The demo board | Uses the board's MicroPython SDK (`ttboard`) to drive `ui_in` and read `uo_out`. `set_inputs()` sets the levels of `ui_in[1..7]` between transfers, so the same pins can carry protocol inputs |
| `PinLink(sel, sck, mosi, miso)` | Any MicroPython board | Bit by bit on four `machine.Pin` objects. Slow, but needs no particular pins |
| `SPILink(spi, sel)` | Any MicroPython board | A `machine.SPI` in mode 0, at most 7.5 MHz with a 60 MHz chip clock (`docs/spec.md`, section 2.1), plus a pin for host select |

## Use

On a PC, after changing anything in `programs/`:

```sh
python firmware/make_programs.py
```

Copy `pe_host.py`, `programs.py` and `demo.py` to the board (for example with
`mpremote cp firmware/pe_host.py firmware/programs.py firmware/demo.py :`).

On the demo board, select the design and give it its clock, then run the
self-test:

```python
from ttboard.demoboard import DemoBoard
tt = DemoBoard.get()
tt.shuttle.tt_um_vrajeshkumar1_janestreetasic.enable()
tt.clock_project_PWM(60_000_000)

import demo
chip = demo.run()
```

The protocol programs assume a 60 MHz clock. The board's firmware generates
the clock by dividing the RP2350's system clock, which it sets to 125 MHz when
a design is selected [1]; 60 MHz is not a whole division of 125 MHz. Its
configuration file has an `rp_clock_frequency` setting [1]; 120 MHz would
make 60 MHz an exact division by 2. Neither has been tried on the board, so
the clock should be measured (for example with the Analog Discovery's
oscilloscope or frequency meter) before the USB and Ethernet programs are
used.

On another board, wired to the FPGA build (`fpga/README.md`):

```python
from machine import Pin
from pe_host import Chip, PinLink
import demo
link = PinLink(Pin(5, Pin.OUT, value=1), Pin(2, Pin.OUT, value=0),
               Pin(3, Pin.OUT, value=0), Pin(4, Pin.IN))
chip = demo.run(link)
```

(the pin numbers are an example; any free GPIO pins work with `PinLink`).

A program on one engine:

```python
from programs import PROGRAMS
chip.load(0, PROGRAMS["uart_tx"])
chip.configure(0, clkdiv=64, side0="out4")   # 8 ticks per bit: 115,385 baud at 60 MHz
chip.pins(out={4: 0})
chip.start(0)
chip.drive(out=[4])
chip.push(0, list(b"hello\n"))
```

The USB device and the Ethernet transmitter:

```python
from pe_host import USBDevice, Ethernet
usb = USBDevice(chip, PROGRAMS)         # engine 3, D+ on io4, D- on io5
eth = Ethernet(chip, PROGRAMS)          # engine 2, TD+ on out6, TD- on out7
eth.send(frame)                         # 60 to 1,514 bytes, without FCS
packet = usb.packet()                   # (PID and bytes, CRC good) or None
usb.prepare(0x4B, [0x12, 0x01])         # DATA1 for the next IN token
```

`Chip` remembers the engine enables, pin owners and pin drivers it has
written, so each helper changes only its own engine and pins.

## Status

`test_micropython_driver` in `test/test.py` runs `demo.selftest()`, the
`USBDevice` helper and the `Ethernet` helper against the RTL, with a link that
moves each SPI byte through the simulated pins. `TTBoardLink`, `PinLink` and
`SPILink` have not been run on hardware.
